## 🔄 工作流程

```
用户请求
  │
  ├─ ① 场景识别
  │     匹配触发词 → 确定S1-S12场景 → 设定风格基调
  │
  ├─ ② 需求澄清（如果关键信息缺失）
  │     谁写给谁？什么场合？字数要求？特别注意事项？
  │     ⚠️ 只问必要的，不问多余的
  │
  ├─ ③ 内容生成（应用六维写作法）
  │     ├─ 定声音（选声音模板或自定义人设）
  │     ├─ 搭结构（结论先行，自然过渡）
  │     ├─ 填内容（具体细节替代空话）
  │     ├─ 控节奏（长短句交替）
  │     ├─ 拿分寸（适度用词）
  │     └─ 埋金句（至少一处亮点）
  │
  ├─ ④ 双层诊断（第三层完整流程）
  │     ├─ 【快车道】案例库快速筛查 → 秒改常见问题
  │     ├─ 【慢车道】五把刀深度追问
  │     │   ├─ 沉浸感知：大声读 → 哪不对劲？
  │     │   ├─ 定格诊断：追五把刀 → 哪把刀切出来的问题？
  │     │   ├─ 还原修正：换成真人表达
  │     │   └─ 回读验证：大声读 → 顺吗？
  │     ├─ 【冲突裁决】快慢冲突 → 以慢为准
  │     └─ 【案例更新】新模式反复出现 → 记录到案例库
  │
  └─ ⑤ 输出
        ├─ 成品文字（直接可用）
        ├─ 诊断说明（如是改写任务，给出五把刀追问结果）
        └─ 质量自评（五维分数）
```
