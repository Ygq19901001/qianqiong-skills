# 文章流畅度诊断

> **用它能解决什么**：文章读着卡？六维度诊断引导流畅度（引导式人工诊断，非自动引擎），附改写建议。

## 相关技能与路由

- 要**去 AI 痕迹** → 用 `humanizer-pro`
- 要**跨语言翻译** → 用 `translate-pro`（含多语种互译与本地化）
- 本技能只做**全文流畅性/逻辑/连续诊断**

- 给我一份润色报告
- 这段太生硬了
- 逻辑连贯性帮我看看
- readability check

## 🚀 5 分钟快速上手（5min Quick Start）

> 你给我一段文字，我告诉你"读起来哪里卡、为什么、怎么改"。三步即可出报告。

**示例输入**（一段产品说明）：
> "我们的产品是具有非常强大的功能性的，它能够对于用户的各种需求进行很好的满足，并且通过智能化的算法实现了效率的显著提升。"

**诊断输出（节选）**：
- 🔴 **流畅性·F3 翻译腔**："对于用户的各种需求进行很好的满足" → 改为"能很好地满足用户的各种需求"
- 🔴 **流畅性·F5 修饰嵌套**："通过智能化的算法实现了效率的显著提升" → 改为"智能算法让效率明显提升"
- **整体评分**：4.2/10（流畅性偏低，套话多）

→ 把上面这段直接发给我，立刻得到一份完整六维诊断引导报告 + 改写版。

## 🔒 硬边界（不可逾越）

- ❌ **不自动改写**：本技能只输出诊断报告与改写建议，绝不擅自替换你的原文。
- ❌ **不自动发布**：不会将诊断结果对外发布或上传任何平台。
- ✅ **关键操作需人类确认**：任何对原文的实质性修改、导出、发布，都必须由你点头确认后才可执行。

## §0 不可变核心

1. **流畅优先**：先诊断阅读流畅度。读不顺的句子，逻辑再对也没用。
2. **场景驱动**：先判断场景，再用场景规则诊断。不用"朋友圈"的尺度量"政府公文"。
3. **有破有立**：每条问题必须给改写建议。不给建议的不诊断。
4. **人读为准**：每条诊断结论，必须用人声通读一遍验证。机械规则可能误判。
5. **信息不动**：改写不改原意，不删关键信息，不加不存在的内容。
6. **继承不重复**：涉及 AI 痕迹问题不重复诊断。如果 humanizer-pro 可用，引用其结论即可。如果 humanizer-pro 不可用，本技能独立完成所有人造词检测，不做降级妥协。
7. **场景自知**：当一个文本跨越多个场景时，以主场景规则为准，副场景规则补充提示。

## §1 技能定位与边界

### 1.1 我是谁

**我是**：一篇文章的"通读体验体检医生"。你给我一段文字，我告诉你哪读起来卡、为什么不顺、怎么改。

**我不是**：不是内容评审（不判断观点对不对）、不是 AI 痕迹检测（那是 humanizer-pro 的事）、不是语法纠错、不是文学批评。

### 1.2 与 humanizer-pro 的分工

| 维度 | humanizer-pro | 本技能 |
|------|-------------|--------|
| 关注 | 是不是 AI 写的 | 读起来顺不顺 |
| 诊断 | 五把刀追问 | 六维系统扫描 |
| 输出 | 成品文字 | 诊断报告+改写建议 |
| 人造词 | 第四把刀一刀切 | 专用子维度分场景评估 |
| 场景 | 12个（含写作风格） | 10个（纯场景分类） |

### 1.3 使用方式

| 输入 | 输出 |
|------|------|
| 单段（<500字） | 六维快速诊断+改写版 |
| 文章（500-5000字） | 逐段诊断+整体报告+改写建议 |
| 长篇（>5000字） | 分段诊断逐批处理 |

**独立运行**：本技能可脱离 humanizer-pro 独立运行。当 humanizer-pro 存在时，§3.5 人造词检测可引用其结论减少重复。当不存在时，§3.5 的 A1-A4+场景容忍度表完全覆盖所有检测需求，无降级。

## §2 触发场景识别：十大场景

### 2.1 十大场景分类

| # | 场景 | 代表类型 | 核心识别特征 |
|---|------|---------|------------|
| 1 | 公文汇报类 | 通知、通报、报告、请示、批复、函、纪要、总结、计划、方案、领导讲话稿 | 含"关于"、发文机关、红头要素、正式落款 |
| 2 | 商业汇报类 | 商业计划书、项目方案、工作汇报、述职报告、竞标书、路演稿 | 数据驱动、结论先行、图表引用、有行动项 |
| 3 | 学术论文类 | 论文、研究报告、开题报告、文献综述、课题申报书 | 引用格式、学术术语、摘要-方法-结果结构 |
| 4 | 演讲发言类 | 演讲稿、致辞、主持词、发言稿、竞聘稿 | 呼语（各位领导）、口语衔接、金句、号召 |
| 5 | 营销文案类 | 产品介绍、广告语、宣传稿、软文、品牌故事 | 情感触发词、CTA、卖点、短句轰炸 |
| 6 | 社交生活类 | 朋友圈、节日祝福、微信聊天、聚会邀请（如"生日派对邀请函"） | 人称明确、口语化、情感温度、篇幅短 |
| 7 | 文学创作类 | 记叙文、散文、小说、诗歌、抒情文、故事 | 描写性语言、比喻拟人、时间空间展开 |
| 8 | 应用文书类 | 书信、启事、证明、读后感、书评影评、正式邀请函（如婚礼请柬、商务请帖） | 格式固定、目的单一、收件人明确 |
| 9 | 新闻评论类 | 新闻稿、通讯、时评、深度报道 | 倒金字塔、5W1H、事实与评论分明、有信息源 |
| 10 | 技术文档类 | 操作手册、技术规范、合同条款、FAQ、说明书 | 步骤编号、术语一致性、条件-动作结构、无歧义 |

### 2.2 场景自动识别流程

```
输入文本 → 扫描特征 → 累加命中得分 → 取最高得分为主场景
  → 两个场景得分差<20% → 标注"混合场景"，取更正式的为主
  → 输出：场景类型+置信度(%)
```

**各场景关键字库（命中计分）**：

| 场景 | 高置信特征（+3） | 中置信特征（+2） | 低置信特征（+1） |
|------|-----------------|-----------------|-----------------|
| 公文汇报 | 发文机关+红头/文号 | "关于…的通知""经研究决定" | 正式落款、抄送栏 |
| 商业汇报 | 数据%+行动项并存 | "Q1/Q2""同比/环比""ROI" | 短段+数据点+建议项并存 |
| 学术论文 | 摘要+参考文献 | "本研究""结果表明"DOI | 章节编号、APA/GB引用 |
| 演讲发言 | 呼语（各位…）+号召结尾 | "今天我演讲的题目是" | 口语衔接词、排比句 |
| 营销文案 | CTA按钮语+痛点描述 | 感叹号>3处、"限时""独家" | 产品卖点列举 |
| 社交生活 | 亲/哈/啦/哦等语气词 | "聚一下""约吗""生日快乐" | <150字短文案 |
| 文学创作 | 比喻+拟人+描写>叙事 | 时间空间展开、对话体 | 段落长短交错 |
| 应用文书 | 收信人称呼+署名日期 | 固定开头（"兹有""特此证明"） | 目的单一、无议论 |
| 新闻评论 | 倒金字塔结构 | 5W1H齐全、"据悉""据报道" | 信息源标注 |
| 技术文档 | 步骤编号（1. 2. 3.） | "注意事项""前置条件" | 术语全篇一致 |

**特殊覆盖规则**（命中即优先）：
- 含"第X步"或"步骤X"→ 技术文档 +4
- 含"关于…的通知/请示/批复"→ 公文汇报 +4
- 含"参考文献"或"[1]"引用格式 → 学术论文 +3
- 全文<80字的祝福/邀请 → 社交生活 +3
- "邀请函"出现在文本标题或开头且含"敬请光临""恭请"等敬词→应用文书+3；含"来玩""聚一聚"→社交生活+3

**置信度基线**：
- 命中≥5分 → 置信度≥80%
- 3-4分 → 置信度60-80%
- ≤2分 → 置信度<50%，询问用户场景

### 2.3 混合场景处理
- 以主场景规则为诊断基准
- 标注副场景，在场景适配维度额外核对副场景要求
- 矛盾时取更严格标准

### 2.4 用户显式指定场景
- "这是我的演讲稿，帮检查流畅度"→ 跳过识别，场景=演讲发言，置信度100%
- "帮我看下这个公文"→ 场景=公文汇报，置信度100%
- "不知道这是什么类型"→ 正常走自动识别

## §3 六维诊断引导框架

严重度标记：🔴 高危（必须改）| 🟡 中危（建议改）| 🟢 低危（可改可不改）

---

### §3.1 流畅性——读起来顺不顺

**核心追问**：一个普通人正常速度阅读时，会不会在某处减速、回读、皱眉？

> **F1 长度判定细则**：以句号/问号/感叹号/分号为句界。
> "列表类不计入"=以下开头的行：bullet（-、*、•）、编号（1.、2.、a)）、或纯并列短语（分号分隔无主谓宾结构）。

- **F1 句子长度**：单句>50字 🟡，>80字 🔴（纯列举类不计入）
- **F2 主谓宾距离**：主谓间修饰>15字 🟡，>25字 🔴
- **F3 翻译腔**："对于…进行了…" 🟢；"进行+双字动词"冗余 🟢（同段3次+→🟡）；"通过…实现了…"（通过后>15字→🔴）；"在…下"滥用（同段3次+）🟡
  > 高频替换：进行处理→处理 / 进行评估→评估 / 进行操作→操作 / 进行管理→管理 / 进行讨论→讨论 / 产生影响→影响 / 作出决定→决定 / 给予支持→支持 / 提供帮助→帮助 / 予以关注→关注
- **F4 被动语态堆叠**：连续3句或同句内"被"2次+ 🟡
- **F5 修饰语嵌套**："的…的…的"三重 🟡，四重+ 🔴
- **F6 同音字混淆**：在/再、的/地/得、做/作、即/既等 🟡（公文/学术→🔴）
- **F7 标点影响节奏**：>200字无标点 🔴；逗号连用6句+ 🟡；破折号/省略号同段3次+ 🟢（文学除外）
- **F8 口语书面混用**：正式语体中插网络口语 🟡（公文/学术→🔴；社交/文学→不判）；反向：口语体中突然插入书卷语（如朋友圈出现"综上所述""究其原因""故""然"）→🟡
- **F9 指代模糊**：指代词往前>2句才找到 🟡；同句两个"其"指不同对象 🔴
- **F10 同义反复/冗余**：相邻句内重复同一信息 🟢（同段3次→🟡）；"真·冗余"（"目前的现状""过去的往事""提前预知"）→🔴

---

### §3.2 逻辑性——论证通不通

**核心追问**：顺着读下来，有没有"嗯？怎么跳到这了？"或"这不对吧？"的感觉？

- **L1 前后矛盾**：同一概念/数据前后不一致 🔴
- **L2 虚假因果**：A推不出B 🔴；"由于…因此…"无实际因果 🟡
- **L3 跳跃结论**：论据到结论缺>1步推理 🟡，缺>2步 🔴
- **L4 并列不当**：不同层级并列 🟡（如"苹果、水果和生鲜"）
- **L5 以偏概全**：绝对化表达无数据支撑 🟡（学术/公文/技术→🔴）
- **L6 循环论证**：用结论解释结论 🔴
- **L7 概念偷换**：前后用词表面相似但内涵不同 🔴
- **L8 逻辑缺环**：读者需要自行脑补才能连得上 🟡；"众所周知""显然"等跳过论证 → 🟡（学术/公文→🔴）

---

### §3.3 连续性——句段衔接是否连贯

**核心追问**：一句接一句读，自然过渡？还是突然断掉或跳走？

- **C1 段落缺过渡**：相邻两段无逻辑衔接词 🟡；场景突然切换——如从"产品参数"跳到下文"企业文化"无任何过渡→🔴
- **C2 主语突然切换**：前句A后句B，B前文未出现 🟡（有"另一方面"等标记则放行）
- **C3 时间空间顺序混乱**：时间线跳跃无标记 🟡（文学类刻意手法除外）
- **C4 代词链断裂**：指代对象往前>3句 🟡；不在当前段 🔴
- **C5 信息重复断裂**：相邻两段重复且非强调意图 🟢；前文提出的概念后文消失 🔴
- **C6 视角切换**：一段内第一/三人称混用 🟡
- **C7 段落长度失衡**：某段>800字而平均150字 🟡；孤立一句<20字 🟢（营销除外）
- **C8 首句断裂**：段落首句非承上而是全新话题，与前段末句无任何关联 🟡

---

### §3.4 完整性——是不是缺了什么

**核心追问**：读完心里会不会冒出"那到底……？"的疑问？

- **I1 缺结论/总结**：文末无收束 🟡（议论文/汇报→🔴）
- **I2 有论点无支撑**：提出观点后面无任何论据 🔴
- **I3 背景信息缺失**：使用概念但全篇无定义 🟡（技术/学术→🔴）
- **I4 对比缺另一半**："相比之下"无对比对象 🟡
- **I5 引用缺出处**："研究表明""数据显示"无来源 🟡（学术→🔴）
- **I6 图/表/附件缺失**：正文说"如下所示"但无图 🟡（草稿→不判只标注）
- **I7 步骤缺失（技术文档专项）**：步骤编号跳跃 🔴；流程缺前置条件 🟡
- **I8 隐含前提**：作者假设读者知道但实际未交代的背景 → 🟡（新手向文档→🔴）
- **I9 缩写未展开**：首次使用专业缩写（如SLA、MTTR）未写全称 → 🟡（专业读者向文档→🟢）

---

### §3.5 人造词恰当性

**继承 humanizer-pro 第四把刀**：判断术语/新词在场景中是否真实流通。

- **A1 识别潜在人造词**：异常中文组合词、非通用音译词、管理咨询腔新词（"打法""闭环""赋能""颗粒度""底层逻辑"等）→标记
- **A2 分场景容忍度**：

| 场景 | 容忍度 | 判断基准 |
|------|--------|---------|
| 学术论文 | 低 | 新术语需有定义+文献支撑 |
| 公文汇报 | 极低 | 不允许管理咨询/互联网新词 |
| 商业汇报 | 中 | 行业通用新词可用，非本行业需审视 |
| 技术文档 | 中 | 领域术语需定义 |
| 文学创作 | 高 | 创新表达允许，影响理解才改 |
| 社交生活 | 高 | 热词梗可用 |
| 演讲发言 | 中 | 有解释的可用 |
| 营销文案 | 中 | 允许创新但读者得懂 |
| 应用文书 | 低 | 须用通用规范用语 |
| 新闻评论 | 中低 | 新词需引号+解释 |

- **A3 判断**：溯源（领域真实用例？）→定义（文中下了吗？）→必要（有通用替代吗？）
- **A4 缩写首次未展开**：专业缩写首次出现未写全称 → 🟡。注意：如果 I9（完整性·缩写未展开）已标记同一缩写，A4 不重复报告。A4 聚焦"非标准缩写"（自造的），I9 聚焦"标准缩写未展开"（如 SLA/MTTR）
- **处理**：确认人造→🟡（非正式）/🔴（正式），建议替换或加定义；无法确认→标注"待核实"

---

### §3.6 场景适配——表达是否符合场景要求

**核心追问**：目标读者读到这个表达时，会觉得"合适"还是"别扭"？

- **S1 正式度不匹配**：正式场景有口语→🔴；非正式场景有公文腔→🟡
- **S2 用语体系不对**：公文用商业腔→🟡；文学用公文腔→🔴
- **S3 结构不符**：新闻无倒金字塔→🟡；汇报无结论先行→🟡；技术文档步骤不全→🔴
- **S4 长度节奏不符**：朋友圈>300字→🟢；演讲稿全无短句→🟡
- **S5 礼貌语气不对**：正式场合称呼失当→🔴；请求用命令→🟡；平级通信过度卑微（"恳请您""麻烦阁下""劳烦您过目"等）+收件人非上级→🟡
- **S6 读者角色错位**：写给领导看用了对下属口吻→🔴；写给客户看用了内部黑话→🟡

## §5 场景专项规则要点

### 公文汇报类
- 额外检查：抬头/落款/日期是否齐全；是否出现"第一人称"叙事（公文应第三人称）
- 禁用：口语词、网络词、感叹号滥用
- 优先级：格式规范 > 逻辑完整 > 语言流畅

### 商业汇报类
- 额外检查：明确结论/建议；关键数据有"同比/环比/绝对值"界定
- 加分：Executive Summary
- 优先级：数据准确 > 逻辑清晰 > 排版可读

### 学术论文类
- 额外检查：引用格式统一；术语全文一致；方法细节能让同行复现
- 优先级：逻辑严谨 > 术语精确 > 语言流畅

### 演讲发言类
- 额外检查：有"呼语"；有金句/记忆点（非强制）
- 特殊：长句可接受度高（有停顿语气）；允许适度重复（不扣分）
- 优先级：节奏感 > 感染力 > 逻辑严谨

### 营销文案类
- 特殊：允许非常规断句；短句轰炸不扣分；需有CTA
- 加分：情感触发、痛点戳中
- 优先级：吸引力 > 节奏 > 信息完整

### 社交生活类
- 特殊：语法/标点大幅放宽；禁用公文腔/管理咨询腔
- 优先级：自然感 > 情感温度 > 规范度

### 文学创作类
- 特殊：允许故意打破所有流畅性规则（效果优先）
- 只诊断"无心之失"（以"上下文风格一致性"判断刻意/无心）
- 优先级：表达效果 > 风格统一 > 流畅性

### 应用文书类
- 额外检查：收件人/发件人/日期齐全；目的第一段明确
- 禁用歧义表达（归入 S2 用语体系，如"大概""可能""也许"）
- 优先级：信息完整 > 格式规范 > 语言流畅

### 新闻评论类
- 额外检查：事实与观点分明；5W1H齐全；信息源标注
- 优先级：事实准确 > 逻辑清晰 > 语言流畅

### 技术文档类
- 额外检查：步骤连续且单步单操作；有前置条件和预期结果；安全提示在操作前
- 特殊：术语必须全文一致；禁止歧义表达
- 优先级：精确性 > 完整性 > 语言流畅

## §6 诊断流程

### 6.1 诊断流程
```
接收文本 → 场景识别(§2)
  ├─ 置信度≥50% → 加载场景权重(§4) → 逐维诊断(§3+§5)
  │    → 人声回读验证 → 输出诊断报告(§7)
  ├─ 置信度<50% 或 0分 → 🛑 中断，询问用户：
  │    "无法自动识别文本场景，请告诉我这是什么类型的文稿？"
  │    （列出十大场景供选择，用户选定后继续）
  └─ 用户显式指定场景 → 跳过识别，置信度100%直接进入诊断
```

### 6.2 分段策略
- <500字：全量诊断一次输出
- 500-3000字：全量诊断，分"关键问题"和"细节问题"两级输出
- >3000字：按段落拆分，每~1000字一批逐批诊断，跨段连贯性全文扫描一轮

### 6.3 诊断耗时上限
- <500字：1分钟
- 500-2000字：3分钟
- 2000-5000字：8分钟
- >5000字：15分钟（可分批）
- 超时→优先输出🔴+🟡，🟢可省略

### 6.4 诊断噪声抑制
**静默跳过**（不产生诊断条目）：
- 文学创作中与全文风格一致的非常规表达
- 社交生活类中明显的网络用语/表情符号
- 标注"草稿""待修订"的段落——仅在报告标注"草稿阶段，未诊断"
- 纯引用块（> 开头）内的文字——不诊断引用来源
- **列表项豁免**：以 bullet（-、*、•）、编号（1. 2.、a)）开头的行，C7"孤立一句<20字"不触发
- **纯代码行豁免**：``` 包裹的代码块或4空格缩进代码行，所有诊断规则跳过

**聚焦原则**：优先报明显影响阅读体验的问题；"理论上可优化但读起来无明显不适"→🟢或跳过

### 6.5 评分标准
每维度满分10分（基准10分，扣分至下限1分）：

| 严重度 | 单条扣分 | 说明 |
|--------|---------|------|
| 🔴 高危 | -3（前2个）/ -1（第3个起） | 首两个各-3，之后每个-1——衰减防止堆叠压死维度 |
| 🟡 中危 | -1.5（前2个）/ -0.5（第3个起） | 同上衰减 |
| 🟢 低危 | -0.5 | 多🟢不扣到6分以下 |

综合分 = 各维度得分加权平均后标准化至60分制。
★★★系数=1.0 | ★★系数=0.65 | ★系数=0.3

### 6.6 冲突裁决
1. 流畅性 vs 逻辑性 → **逻辑性优先**（逻辑错了读再顺没用）
2. 流畅性 vs 场景适配 → **场景适配优先**
3. 连续性 vs 完整性 → **完整性优先**
4. 任何维度 vs 文学刻意手法 → 以**上下文风格一致性**裁决

## §8 边界与免责

### 不做诊断
- 纯数据表格、代码块
- 诗歌（除明显用词错误外）
- 单句<15字且无上下文
- 标注"草稿""待修订"的段落——仅在报告中提示"草稿阶段，未诊断"
- 引用块（> 开头）内的文字——不诊断他人原文

### 不确定时
- 标注"†疑似"而非确认——"†"前缀表示有人工确认空间
- 场景置信度<50%→询问用户场景
- 文学类不确定刻意/无心→标注"†可能是创作手法，请判断"
- 跨场景混合文本→提示主场景局限性，建议副场景补充
