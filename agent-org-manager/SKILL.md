# Agent Organization Manager

## 一句话看懂

**把你的多个AI助手组建成一家小公司：每个AI做一个"部门"、互相协作、自动日报、自动质检——你只管定方向。**

不是让一个AI帮你做事。是让一群AI像公司一样运转。

---

## 为什么要用这个？

一个AI做不了所有事。让它写内容、管数据、审质量、做备份——它一定会崩溃或者糊弄你。

把工作拆给7个"部门AI"：数据部、品牌部、财务部、法务部……每个只做一件事，自动协同。你最多看看日报就知道公司今天干了什么。

这就叫"一人公司"——不是一个人干所有事，是一个人管一家AI公司。

---

## 3分钟快速上手

### 第1步：建公司花名册（1分钟）

创建一个文件 `company/shared/ROSTER.md`，写清楚你的"公司"有几个部门：

```markdown
# 公司花名册

| 部门 | Agent名称 | 角色 | 优先级 |
|------|----------|------|--------|
| CEO | main | 定方向、做决策 | P0 |
| 数据部 | datacenter | 信息采集、监控 | P0 |
| 品牌部 | brand | 内容创作、发布 | P1 |
| 监察部 | inspector | 质量抽查、合规 | P0 |
```

最少3个部门就可以开始。想加就加，不想加就删。

### 第2步：让部门互相通讯（1分钟）

AI部门之间怎么说话？三条路并行，确保一条断了还有备用：

| 方式 | 速度 | 用途 |
|------|------|------|
| `sessions_send`（直接喊话） | 秒级 | 实时通知、紧急报警 |
| 共享文件（写便条） | 稍慢 | 日报、交接、归档 |
| 云文档（写在线笔记） | 稍慢 | 跨设备查看、长文档 |

通讯规则很简单：
- 不知道发给谁？→ 发给行政部
- 合规问题？→ 发给法务部
- 违规了？→ 发给监察部
- 数据请求？→ 发给数据部
- 花钱的事？→ 发给财务部

### 第3步：定日报和质检（1分钟）

设定两个自动任务（用定时任务cron——你可以理解为"闹钟提醒AI去干活"）：

**晚间日报**：每个部门每天22:00自动写一句话汇报：今天做了什么、明天做什么。

**巡检**：每天10:00、14:00、22:00三次，监察部自动检查：日报写了吗？有异常吗？连续出问题的标记出来。

就这么简单。后面要加学习日报、月度审计之类的，按需加。

## 核心设计

### 部门架构

```
        CEO（你）
        /   |   \
     数据部  品牌部  销售部
        \   |   /
         监察部（独立审计所有部门，包括你）
```

### 通讯防污染铁律（非常重要）

这是最容易被忽视但最致命的问题——一个部门的垃圾数据流进另一个部门的文件里。

- 每个部门有自己的文件夹：`company/departments/品牌部/`，绝对不写到别人的文件夹里去
- 共享信息走 `company/shared/`，不走部门文件夹
- 一个部门出bug不会影响其他部门——出问题的文件隔离、不传播
- 写进共享区之前先检查：数据对、时间对、来源对

### 多链通讯（单点故障的克星）

一条路断了是灾难，三条路并行就没事。每次跨部门通讯至少走两条路，推荐三条。

每月做一次演练：关掉一条路，看另外两条还能不能通。

## 扩展玩法（按需添加）

建好基础之后，可以加这些：

**每日学习**：每个部门早上搜自己领域的新闻，写300字笔记。

**学习系统**：数据部持续收集行业信息，品牌部持续研究内容风格。

**全面质检**：监察部不仅看日报，还抽查发布内容质量、检查数据准确性。

## 常见问题 FAQ

**Q：我不会写代码，能用吗？**
A：能。整个过程只需要复制粘贴模板，改部门名称就行。难度等于填Excel。

**Q：最少需要几个AI助手（Agent）？**
A：3个就可以起步：CEO（你）+ 一个干活部门 + 一个监察。少于3个就没什么"组织"可言了。

**Q："sessions_send"是什么？**
A：你可以理解成"AI之间的微信消息"。一个AI可以直接给另一个AI发话，不需要经过你。

**Q："cron"是什么？**
A：定时任务。就像设定闹钟，到点了自动让AI去干一件事。比如"每天晚上10点写日报"。

**Q：为什么需要监察部？**
A：没人检查的事一定会慢慢坏掉。AI可能悄悄出bug不告诉你，等你发现已经坏了3天。监察部就是你的"眼睛"。

**Q：我的AI隔几天就不动了怎么办？**
A：给监察部加一个"心跳检测"：每个部门每小时写一个心跳文件，监察部发现24小时没心跳的就报警。这就跟服务器监控一个道理。

**Q：通讯"多链"真的有必要吗？**
A：如果不做，第一次某条路断了你会找半天原因。做了之后，一条断了另外两条自动顶上，你甚至感觉不到。这是从生产环境教训里来的。

**Q：怎么判断哪个部门该做什么？**
A：一个简单原则：把一类事情交给一个部门。内容全归品牌部、钱全归财务部、质检全归监察部。一个部门只管一件事，不要交叉。

## 运行时稳定性保障（QP 韧性体系）

本技能为 Prompt 型技能，稳定性通过以下机制保障：

### 输出一致性校验
- 同一输入多次运行时，核心结论应一致（允许表达方式差异）
- 若输出出现显著矛盾，优先回溯最后一次修改的源头
- 引用型数据以原始来源为准，不因模型采样差异改变结论

### 异常输入降级链
```
正常输入 → 完整流程
    ↓ 关键信息缺失
    追问补充（1轮）→ 仍不足？→ 标注「信息不足」+ 给出最小可行输出
    ↓ 超出能力边界
    硬边界拦截 → 明确告知「不在能力范围」+ 建议替代方案
    ↓ 模型采样不稳定
    核心结论不变 → 仅标注「表达可能存在微调」
```

### 重试与恢复指引
| 场景 | 处理 |
|------|------|
| 输出明显偏离工作流程 | 用户可追加「请严格按工作流程重新执行」触发重试 |
| 数据引用不一致 | 以首次引用来源为准，后续引用追加「已核实与首次一致」 |
| 中间步骤遗漏 | 用户可指定步骤号要求补执行 |
| 外部依赖不可用 | 标注「外部依赖暂不可用」+ 使用缓存/已知数据替代，不静默跳过 |

### 用户干预入口
- 任何步骤输出不满足预期时，直接指出问题即可触发修正
- 不需要重新描述全部需求，模型保留上下文并增量修正
- 连续 2 轮修正失败 → 建议缩小范围或拆分子任务

## QP 错误码（专用段 E1001+）

| 码 | 含义 | 修正引导 |
|----|------|---------|
| QP-E1001 | 花名册缺失 | 先建公司花名册（角色/部门/汇报线）再启部门 |
| QP-E1002 | 通讯链断裂 | 检查部门间消息通道配置与路由规则 |
| QP-E1003 | 日报缺失 | 配置日报 cron + 质检规则，确认 agent 有汇报入口 |
| QP-E1004 | 质检未生效 | 检查质检 prompt 与评分阈值配置 |
| QP-E1005 | 角色冲突 | 同一职责多个 agent 时明确主从/分工 |

## 输入/输出约束

| 项 | 约束 |
|----|------|
| 输入 | 组织需求（部门/角色/通讯/日报/质检） |
| 输出 | 花名册配置 + 通讯路由 + 日报/质检规则 |
| 前置 | 明确各部门职责边界，避免角色冲突 |
